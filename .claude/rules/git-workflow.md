# Git workflow rules

- **`.claude/` is ignored with `.claude/`; deeper `!` negations do NOT re-include children.** Git cannot re-include anything under an excluded directory. Use `.claude/*` then `!.claude/commands/` etc., and re-ignore `settings.local.json`, `launch.json`, `worktrees/`. Verify with `git check-ignore -v`. (source: codex-review 2026-09-02, finding 10)
- **Never execute a plan from a dirty checkout on another task's branch.** Create a dedicated worktree from fresh `origin/main` on `claude/<task>` or `codex/<task>` (AGENTS.md §0 prefixes; `setup/*` is not allowed). `codex-execute` worktrees from HEAD and reapplies its diff to the original checkout by default; disable that and commit inside the worktree. (source: codex-review 2026-09-02, finding 1)
- **Commit before push, and verify.** A command that writes files then pushes leaves them local. Order: refuse on `main`/detached HEAD → show scoped file list → approval → commit → push with `-u` when no upstream → assert `git rev-parse origin/<branch>` equals HEAD → report push failures, never claim success. (source: codex-review 2026-09-02, finding 12)
- **Ship order is docs → tests → review → remediate → approve → commit → push → PR.** Committing a dirty tree first captures unrelated work and leaves later doc/changelog edits out of the commit. Enumerate and confirm exact files in scope before anything is staged. (source: codex-review 2026-09-02, finding 2)
- **Smoke tests of git-mutating commands run against a throwaway repo with a local bare `origin` and stubbed `gh`/`codex`.** Never "smoke-run" a command that commits, pushes, or opens PRs against the real remote. (source: codex-review 2026-09-02, finding 7)
- **`git diff <base>...HEAD` reviews commits only.** It omits staged, unstaged, and untracked changes, which is exactly what a ship command is about to commit. Stage the confirmed set and review `git diff --cached <merge-base>`. Likewise a session summary must inventory committed / staged / unstaged / untracked separately, and never claim "session closed" with approved work uncommitted. (source: codex-review 2026-09-02 r2, findings 5, 11)
- **Never hardcode `origin/main` in portable commands.** Resolve the default branch via `git symbolic-ref refs/remotes/origin/HEAD` (fallback to rendered config). Creating a branch from `origin/<default>` with a dirty tree can transplant or clobber changes; use `git switch -c` from HEAD, or require a clean tree. (source: codex-review 2026-09-02 r2, finding 6)
- **Never `cp -r .claude` to another repo.** This checkout's ignored `.claude/worktrees/` is ~7 GB and `settings.local.json`/`launch.json` are machine-local. Package from git's tracked allowlist (`git archive HEAD .claude`) or an enumerated path list. (source: codex-review 2026-09-02 r2, finding 3)
- **Branch-protection hooks must parse the refspec, not the current branch.** `git push origin HEAD:main`, `refs/heads/main`, `+main`, `--force*`, `git -C dir push`, and chained commands all bypass a "current branch" check. Resolve the default branch dynamically (`main`/`master`/`trunk`). `git worktree add <path> origin/main` yields detached HEAD; always `-b claude/<slug>`. (source: codex-review 2026-09-02 r3, findings 3, 4)
- **Generate docs/changelog before confirming the commit scope, and re-run typecheck/lint/test after any security remediation.** Otherwise the confirmed file set omits generated files, or the final commit is unverified. (source: codex-review 2026-09-02 r3, findings 5, 7)
- **`git archive HEAD .claude` is not an allowlist.** It ships every tracked path under the dir (fixtures, harness). Pass each allowed path explicitly. Every re-included `.claude/` subdir needs its own `!` line. (source: codex-review 2026-09-02 r3, findings 8, 9)
- **Push guards must fail closed on implicit and multi-ref pushes.** Bare `git push` (upstream on default), `feature:main`, `--delete main`/`:main`, `--all`, `--mirror`, configured push refspecs, `env git`/absolute paths/aliases all reach the default branch. Resolve every destination; block unless all are non-default. `git worktree add` needs separate paths for existing worktree / local-only branch / remote-only branch / new branch. (source: codex-review 2026-09-02 r4, findings 3, 5)
