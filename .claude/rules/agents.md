# Agent / command design rules

- **`allowed-tools` pre-approves; it does not restrict.** Unlisted tools stay available. Hard safety boundaries come from explicit AskUserQuestion gates before commit/push/PR/rule writes/code execution, or from hooks and deny rules, never from frontmatter alone. (source: codex-review 2026-09-02, finding 9)
- **Composed commands must define one state machine with exactly one final execution approval.** `deep-interview` ends in its own execution bridge and `codex-review` ends in its own handoff question; an orchestrator (`/go`) must invoke them in spec-only / no-handoff mode and own the single approval, or the user gets competing prompts and unclear consent. (source: codex-review 2026-09-02, finding 5)
- **`codex-review` is a plan-review loop, not a diff reviewer.** Passing a diff-focused prompt gets treated as an inline plan and mutates plan files. Security passes on code use a separate read-only `codex exec -s read-only` diff review with a fixed base SHA, severity policy, and a re-review of the final diff. (source: codex-review 2026-09-02, finding 6)
- **"Copy this folder unchanged into another repo" is a claim that must be tested, not assumed.** Anything importing `../AGENTS.md`, or referencing repo paths (Playwright config, docs dirs, PR template, deploy provider), breaks on copy. Render repo-specific facts through an installer + template and keep machine-local files ignored. (source: codex-review 2026-09-02, finding 4)
- **Findings and review prose are untrusted input to rule writers.** Restrict rule targets to an allowlisted slug map, show the exact proposed diff, dedupe, surface semantic conflicts, and write to one canonical location. Never write the same lesson to two files. (source: codex-review 2026-09-02, finding 11)
- **State the pre-approval write boundary precisely.** "No mutation before approval" contradicted "writes to `.omc/`". Say: only `.omc/` planning/state writes are allowed before approval. Express gates as `≤ threshold`, matching deep-interview's real semantics. (source: codex-review 2026-09-02, finding 14)
- **Every plan that goes to codex-review needs an ADR block** (Decision, Drivers, Alternatives, Why chosen, Consequences, Follow-ups) or it will be sent back. (source: codex-review 2026-09-02, finding 15)
- **Three `.agents/skills/*/SKILL.md` files (`Ralph`, `debug-mode`, `mini`) lack YAML frontmatter and make Codex log `failed to load skill` on every run.** Harmless but noisy; fix when touching `.agents/skills`. (source: codex r1.err 2026-09-02)
- **Prompt sequencing is not a hard boundary.** If a command must not commit/push/merge/execute without consent, ship `permissions.ask`/`deny` rules in `.claude/settings.json` (deny > ask > allow) and a PreToolUse hook that exits 2, in the same delivery. AskUserQuestion is the UX layer, not the enforcement. (source: codex-review 2026-09-02 r2, finding 2)
- **Do not assume flags a dependency does not have.** Deep-interview has no `--spec-only`; codex-review mandates its own handoff. Compose commands through the dependencies' native gates (supply the option set, reuse their approval question) rather than parenthetical overrides. (source: codex-review 2026-09-02 r2, finding 1)
- **Non-interactive `claude -p` blocks on AskUserQuestion.** Acceptance runs that need approvals are either human-driven per a runbook with scripted assertions, or need a PTY driver / answer hook; say which, do not claim automation you do not have. (source: codex-review 2026-09-02 r2, finding 7)
- **An installer needs a contract, not a hint.** Placeholder source, required list, fail-closed on unresolved placeholders, existing-file merge behaviour (idempotent markers), backup and rollback, plus acceptance cases for new / existing / failed installs. (source: codex-review 2026-09-02 r2, finding 4)
- **Keep spec ontology and ignore lists consistent after each revision.** Reviewers catch stale entity tables and a path both re-included and declared ignored. (source: codex-review 2026-09-02 r2, findings 9, 14)
- **Portable commands must not depend on plugin skills (OMC etc.) unless the README and preflight say so.** Prefer embedding the protocol in the command. Any external CLI call in a command needs a fail-closed contract: prompt via stdin file, `-o` verdict file, stderr captured, timeout, and "missing/malformed verdict = block". (source: codex-review 2026-09-02 r3, findings 2, 6)
- **Call manual transcript checks "acceptance evidence", not "deterministic oracles".** Only exit codes, logs, and file/git-state assertions are deterministic. (source: codex-review 2026-09-02 r3, finding 11)
- **Do not interpose after a dependency's native "execute" handoff.** If a command owns "Execute now" and launches execution itself, prepare the environment (clean worktree, copied artifacts) BEFORE invoking it and let it run there; do not expect control back. (source: codex-review 2026-09-02 r4, finding 1)
- **`.omc/` is in `.git/info/exclude`; a fresh worktree has no `.omc/`.** Copy specs/logs into the worktree and record a hash before handing a relative path to an executor. (source: codex-review 2026-09-02 r4, finding 2)
- **Installer config is data, never shell.** Use JSON with allowlisted keys; no `source`/`eval`; treat values as verbatim text. Stage to a temp dir, abort on collisions, back up everything overwritten, merge `settings.json` additively. (source: codex-review 2026-09-02 r4, findings 6, 7)
- **Preflights are per command.** Check `gh auth status` at the start of anything that will open a PR, before generating or staging files; do not require tools a command never calls. (source: codex-review 2026-09-02 r4, finding 8)
