# Testing rules

- **Visual/Playwright commands attach, they never start servers.** Root `playwright.config.ts` has a `webServer` block with `reuseExistingServer`, which starts the dev server when none is listening, violating the "only the app-runner runs dev servers" rule. Use a plain Node Playwright script with no `webServer`; if nothing listens, stop and tell the app-runner what to run. (source: codex-review 2026-09-02, finding 3)
- **Browser automation gets a host allowlist and read-safe interactions.** Only `localhost` or hosts listed in CLAUDE.md "Repo surfaces"; a local server may still hold prod credentials, so no form submits, deletes, purchases, integration connects, or messages unless the step is named in `--flow` and confirmed. (source: codex-review 2026-09-02, finding 3)
- **Acceptance criteria need deterministic oracles.** "Clicks through", "fixes defects", "loads without error" are not testable. Give each AC a route, expected state, exact evidence, and cover missing prerequisites, cancellation, dirty/main/detached git states, failed review, and forbidden side effects. (source: codex-review 2026-09-02, finding 13)
- **Non-localhost test hosts are read-only, always.** Even an allowlisted staging host gets navigation only; scripted side effects (submit, purchase, send, connect) are localhost-only, one confirmation per step, with a fixture that proves zero hits. (source: codex-review 2026-09-02 r2, finding 12)
- **URL allowlists need structural parsing and redirect re-validation.** Reject userinfo and lookalike hosts, compare exact normalized hostnames, and re-check `page.url()` after every navigation before screenshotting. Any "preview URL" promise needs bounded polling with explicit pending/unavailable outcomes. (source: codex-review 2026-09-02 r4, findings 10, 11)
- **Verify a PATH shim exists before invoking a stubbed CLI in tests.** `mktemp -d` pre-creates the dir that the harness `setup.sh` refuses, so no stubs were installed and a smoke `gh pr merge` reached real GitHub (harmless only because the PR was already merged). Always `command -v gh` and assert it resolves inside the harness `bin/` first, and source the harness `env.sh`. (source: codex-execute 2026-09-02)
- **Log-scanning assertions must match the real log format.** The merge check required whitespace before `pr merge` while the stub wrote `argv=pr merge`, so a merge slipped through. Test every negative assertion against a deliberately tainted log before trusting it. (source: codex-execute 2026-09-02)
