# Claude/ChatGPT shell (apps/web)

Last Modified: 2026-07-26

## Overview

Dashboard chrome inspired by Claude/ChatGPT and ClickUp: top bar with centered Search ⌘K and a top-left PanelLeft control for AI Chats, icon-rail HQ sidebar (always collapsed), a resizable left AI drawer with chat history, a Space work dock (no open-item tab strip), a shared artifact slide-out, and a right summary panel (Tasks / Files / Sources).

Design reference: `.docs/design/claude-chatgpt-shell-v4/` (HTML prototype + `shell-state.md`).

## Data Flow

1. `useShellStore` (`components/shell/use-shell-store.ts`) owns chat drawer/history widths, page work-area collapse, the shared artifact viewer, right panel, and page breadcrumbs. Legacy sidebar pin/peek prefs are cleared so the HQ rail stays icon-only.
2. `DashboardFrame` renders a full-width `ShellTopBar`, then a row of HQ sidebar + `ShellWorkspace` (T-junction — sidebar under the top bar, never overlaying it). On `/spaces`, `ShellWorkspace` keeps the Space page mounted inside `SpaceWorkDock`; collapse hides the dock and shows full chat without unmounting Space.
3. Feature pages publish rich breadcrumbs with `ShellBreadcrumb`; `ShellTopBar` renders them in place of the path-label fallback. Publishers today: Team, Spaces, Flows, Skills.
4. Top-bar PanelLeft expands/collapses the AI chat drawer (not the HQ menu). The purple control always combines the drawer icon with the **AI Chat** label so the action remains clear in either state; the HQ rail stays icon-only.
   4b. Global Search is the centered top-bar control. Search opens `StudioSearchModal` (⌘K; idle until you type). **AI Chat** is the top-left PanelLeft control: click opens/collapses the drawer.
5. Rail lists Home, Team, Programs, Brain, More (flyouts). Home expands to Home / Inbox / Meetings / My Tasks, followed by real pinned/favorite campaigns and Spaces when available. Chat history lives inside the AI drawer. Slack-origin rows show a channel badge via `ConversationChannelIcon` / `metadata.source`.
   The history rail has its own persisted drag width and collapse state. Dragging it fully left or using its collapse control leaves the active chat open with a compact restore button attached beside the HQ rail. The outer drawer resizes independently and can reach the viewport edge; releasing there enters full-screen chat and preserves the prior docked width for restoration. Search expands from its icon and collapses on outside click. Explicit agent filters appear as removable chips beneath **New chat**; removing a chip changes the real history query. Pixel's default view is unfiltered.
6. Opening a conversation in the drawer stays on the current workspace page. Home full chat uses `/home?conv=` / `/home?chat=new`. Top-bar pencil on workspace: if the drawer is closed → `restoreChatDrawer()` (last chat); if open → fresh chat.
7. Open in ▾ resolves Drive / Google Docs / Canva targets from the focused space `?item=` (and optional media focus). Canva targets are lazy: the shell does not generate or import a design until the user selects Canva.
8. The right summary action is context-aware. With an active chat it exposes Tasks, Files, and Sources scoped to that conversation: completed agent tool activity, saved conversation artifacts/documents plus message attachments/media, and explicit references/links. Without an active chat, including generic Home, it exposes only the existing personal Tasks queue.
9. A Space chat header shows the conversation's saved campaign / Space scope. Selecting another Space atomically retargets the conversation and future agent work; selecting **General** clears the Space while leaving the visible workspace open.
10. Chat presentation is mode-aware: full chat can show an inline-renamable title beside the agent when a title exists; docked and untitled chats omit the title (no “New chat” placeholder). The top bar always shows the page crumb, not the chat name.
11. Submitting the Home new-chat composer clears any prior active conversation, queues the message with `railIntent: 'new'`, mounts the full chat at `/home?chat=starting`, then replaces that temporary URL with `/home?conv=` as soon as the new conversation is created.
12. Artifact chips, chat outputs, Space artifact/media cards, Brain source previews, Space document visuals, and the Files summary tab publish the shared `@/lib/artifacts` shell-viewer target. The shell opens one resizable right-side viewer, swaps content in place, and closes it on top-level navigation.
13. Space-backed document targets load the real Space item into the canonical document editor's inline mode, including the owning Space's fields, Doc/Visual views, fixed rich-text toolbar, grouped Copy/download actions, Google Docs export, settings/share controls, and autosave route. The shared viewer can expand that same editor to full screen without swapping renderers. Generic documents and files without a Space item continue to use the read-only deliverable renderer. **Open in Space** launches the same document in its full Space destination. Image targets open the same creation studio from chat, Campaign, and Space surfaces. The studio uses the same multimodal image route as chat for GPT and Gemini edits, supports one or more reference images, exposes Square / Portrait / Story / Landscape / Widescreen actions in the top toolbar, and saves every edit back to the source conversation. The editor keeps a fixed, scrollable conversation timeline with the selected version highlighted, fits tall images inside the viewport, and provides a floating prompt composer with reference uploads and voice transcription. It downloads the actual image file and offers icon-led **Open in new tab**, **Open in Canva**, and **Open in chat** actions. Opening media never attaches it to the active conversation.
14. `/artifacts` is the account-wide artifact library. It paginates through docs and media, merges every campaign-artifact family from the active organization plus personal legacy assets owned by the signed-in user, labels each row with its campaign or Space, and opens rows in the shared viewer. Uploaded assets are hidden by default and available through the source filter. Type filters include Docs, Images, Videos, Sheets, Presentations, Funnels, Campaign assets, and Files. Video rows and cards render a muted first-frame preview and open in the shared video viewer. More → Artifacts links here; Space-specific views remain inside their Space.
15. Forking an assistant turn creates a new conversation with the original messages through that turn, adds it to chat state, and navigates to the canonical `/home?conv=` URL for the returned fork id. The success toast is shown only after creation succeeds.
16. Every shared Chat composer can attach a person from the `@` menu or the plus menu. **People** combines active portal teammates with Slack-only managed people in the active organization. The server validates the selected identity, resolves its managed Person Brain or canonical User Brain, and adds that durable person context to the agent turn. The Home composer loads People even when no campaign is selected.
17. Empty-chat action and capability chips select an executable quick-start workflow, seed the visible request, and attach a hidden routing contract to that message. The contract names the matching read/write actions, requires a successful tool receipt before claiming completion, and remains active only while the seeded request prefix is intact. The composer shows the selected workflow as a removable chip. **Daily Brief** replaces the unsupported StandUp shortcut and reads the signed-in user’s private briefing/agenda sources; **Delegate** replaces the vague Super Agents shortcut and creates real managed-agent work.
18. Home layout preference version 2 re-seeds old local and server layouts once to full-width Agenda + Inbox. Users can still customize the dashboard and add the lazy-loaded Ask ROAS composer.
19. Inbox reads `user_notifications` through the dedicated missions-notifications controller. `inbox_bucket`, `snoozed_until`, and `cleared_at` stay independent from `read_at`; one RPC returns unread counts for Primary / Other / Later / Cleared. Inserts are classified by type, realtime inserts use the same client predicate, and clear/snooze/move/read actions update optimistically with rollback.
20. Inbox, Meetings, and My Tasks use full-page presentations on their dedicated routes. Inbox uses a responsive list/detail workspace: selecting a row marks it read and keeps its full context plus triage actions visible, native task/mission details open without leaving Inbox, and **View source** navigates to the originating Space, Mission Control item, DM, or integration. Search, mark-all-read, and clear-current-view actions support fast queue triage. Shared selectors render the selected label instead of an empty native-looking control, and Inbox dates reserve a stable column so rows align.
21. Chat-history filters render in a body portal so shell flyouts cannot cover or clip them. The Chats and Tasks work page opens a selected conversation in the left drawer without navigating back to Home or closing the work page.
22. Team agent detail uses the canonical AI Chat drawer instead of rendering a second agent-chat runtime. Entering an agent selects that agent, opens a blank canonical chat, expands the history rail, filters history to that agent, and keeps the Team surface attached as visible removable context. The full agent grid remains in the work area while the selected agent profile opens in its right-side detail panel.
23. The page expand/contract control renders only when chat has actually created a collapsible page relationship or the page is currently hidden. Closing a full-page Home conversation returns to the main Home surface. The outer work-area wrapper is the only reveal-transition owner: it clips one right-anchored page surface, while the inner page has no second transform or animation.
24. Visible chat work context is rendered as one compact control inside the composer footer next to the model selector. The control names the attached context, explains on hover what the selected agent can use, removes it with `×`, and opens the context picker with `+`. With no work context attached, the picker becomes a transparent **Add context** action. My Tasks uses the shared leading-icon input geometry so the search icon and placeholder never overlap.
25. The default Pixel empty state shows only Pixel's name and capabilities; it does not render an organization-role subtitle. The agent picker keeps Pixel first, followed by a labeled **Other agents** section.
26. Selecting a history row writes that exact conversation into the canonical chat store before opening the drawer. The mounted chat panel waits until the selected row is resolvable, merges it into its local list, and then selects the conversation and its saved agent. The shell artifact-viewer adapter remains mounted while hidden so image-open events from either the inline preview or output card can create the first viewer target. Once a target exists, the viewer replaces the mounted page work area; closing it restores that same page state.
27. Empty chats render agent selection once in the centered identity. Its chevron appears on hover and opens the agent roster. Established conversations retain the header picker because the centered identity is no longer present. The full Chats and Tasks page aligns its compact heading with the conversation list and shows updated dates plus row dividers without an extra rule beneath the page header.

## Decision Log

- Space work collapse (`PanelRight`) hides the Space **dock** beside chat; Space stays mounted so selection/scroll survive expand. Docs/tasks open in normal Space UI — no shell open-item tab strip. Entering or switching `?space=` auto-opens the dock so a prior collapse does not stick. Artifact viewer stays a separate dock. List / summary panel is unrelated.
- Page work-area collapse is available on shell routes only when chat is open or the page is already hidden. The page body moves beyond the right edge while chat expands; **Show page** slides it back from right to left. Dragging the outer AI drawer to the viewport edge enters the same collapsed state. Full-page Home chat closes back to Home rather than revealing an empty shell state.
- Peek overlays as a fixed solid column under the top bar (does not push main); pin is in-flow 272px. Collapsed rail keeps inset `card-glass`. **Current product default:** HQ rail stays icon-only; top-bar PanelLeft drives AI chat instead of sidebar expand. Home/Work mode toggle and Work menu removed.
- The right summary panel follows the active conversation instead of the visible Space. Chat Files includes conversation documents/artifacts and message attachments/media; Sources includes explicit message references and links; Tasks includes completed and failed agent actions persisted in the chat history. Generic Home shows Tasks only.
- Top-bar ⋯ omitted until real section/chat actions are wired.
- Home flyout rows (Team/Campaigns/Brain/More) have no trailing chevrons — hover still opens the docked flyout.
- Collapsed rail More (•••) hosts Projects + Flows + Artifacts (same `HubDockFlyout` as expanded More). Projects keeps a nested hover flyout; Flows and Artifacts are direct links (`/flows`, account-wide `/artifacts`). Space-level Docs, Media, and custom artifact views remain owned by the current Space.
- Campaigns flyout uses a nested spaces sub-flyout on campaign-row hover (400ms grace); not an inline accordion. No Favourite/Campaigns captions inside the flyout body. Campaign rows share the same `hub-dock-flyout-row` gap as nested space rows.
- Dock flyouts use a left hover bridge + tight offsets (primary 2px / nested 0) and ignore leave when the pointer moves into another `[data-hub-dock-flyout]`, so parent → nested paths stay reachable. Vertical position is clamped to the viewport after measure.
- Disabled Brain scopes show muted “Enable in Manage Brains” rows linking to Manage Brains.
- The top bar owns centered global Search / Cmd-K only; chat open/new controls live with the chat surfaces instead of competing with Search.
- **AI Chat** is the always-labeled purple PanelLeft control in the shell top bar (opens/collapses the drawer). The HQ rail under the ROAS logo is logo → Home / Team / Programs / Brain / More only — no under-logo AI Chat pill.
- Chat history lives inside the drawer beside the panel and can be resized separately. Default leading icons are off (Claude/ChatGPT-style text list); filter can still show agent / channel / status marks. History rows use compact `body-3` titles with `px-spacing-1` / `py-spacing-1` / `gap-spacing-1` density and no redundant outer horizontal gutter, so more chats and more of each title remain visible. The timestamp remains available as the row tooltip, while the overflow action appears on hover without permanently consuming title width. Newly created conversations merge into the live history immediately and are replaced in place as their generated title arrives.
- Chat history can collapse independently from the active conversation. Dragging the history divider beyond its left threshold or selecting its collapse action persists a narrow restore rail; it never changes the outer AI drawer width.
- Conversation titles are short Gemini topic labels from the first user message (3–6 words), not the raw first line. Studio/shell schedules suggest-title on the first turn; Slack conversations retitle on first inbound message; opening history auto-titles up to 12 existing raw / `Slack Chat` rows via `POST /api/conversations/:id/auto-title`.
- `RootProviders` enables transient product scrollbars: thumbs are transparent while idle, become visible for active scroll events, and hide again after the activity window.
- Chat-menu **New** on workspace routes always docks a fresh chat (does not dismiss Space/work content) and sits full-width under the history Search/filter row with `rounded-spacing-2`.
- Chat menu conversation toolbar is Search + filter (defaults: active status, flat list, no leading icons), with **New chat** full-width beneath. Filter options expand inline on click (Type / Status / Last activity / Group by / Icon). Icon chooses agent avatar, channel logo, in-progress/done status, or none; selecting Agent also loads all-agent conversations in the shell drawer. Reset to defaults restores the default filter state. Global Studio search is the centered top-bar Search / Cmd-K only. Established conversations keep the agent picker in the main chat header; empty chats move it into the centered identity so the active agent is not rendered twice. The chat panel **X** closes the drawer.
- The full Chats and Tasks page uses compact dated rows with dividers and aligns its heading to the list. Embedded chat-history rails remain denser and keep timestamps in row tooltips so permanent dates do not reduce title width.
- Global Search uses the shared entity-search boundary. Core entities paint independently from the heavier artifact lane; the retired `/api/studio/search` route must not be reintroduced.
- Home defaults to full-width Agenda + triage Inbox cards. The Home flyout also provides full-page Inbox, Meetings, and My Tasks routes plus a bounded list of real pinned/favorite campaigns and Spaces. New Chat (history-toolbar New / `?chat=new`) remains the full former Home hero: greeting, composer, templates, recommendations.
- Dedicated Home destinations use page presentation rather than a floating dashboard-card shell. The Inbox card and page share the same responsive list/detail workspace. Opening native details and viewing the source are intentionally separate actions: the first preserves triage context, while the second changes workspace. Shared Inbox filters always display their selected value, and list metadata columns stay aligned.
- Team agent detail opens the authoritative shell composer with the selected agent and Team context. The history rail shows only that agent's conversations by default, while the Team work area keeps the agent profile visible. The retired Team-specific composer and conversation warmer must not be reintroduced.
- Inbox triage uses orthogonal bucket, snooze, clear, and read state. Snoozing never destroys Primary/Other ownership, clearing never marks an item read, and an expired snooze returns to its saved bucket.
- Empty **docked** chat drawer uses a ClickUp Brain–inspired empty state: active-agent hero (Pixel + lamp for the default agent), perpetual marquee capability starters under the hero (pause/expand on hover; select a real workflow; clearing or replacing the seed removes its routing), and verb action pills above the input (Find / Research / Create / …). Capability chips = what to deliver; action pills = how to approach. Each selection is visible in the composer and routes the completed request to real platform tools. Daily Brief uses private personal briefing sources instead of a fake standup workflow; Delegate creates managed-agent work instead of simulating “Super Agents.” Full `/home?chat=new` still owns the Home template fan / “For you” extras.
- Untitled chat panels no longer show a redundant “New chat” title in the header; only a real conversation title appears (full layout), and docked chrome keeps agent/scope/actions only.
- The new-chat agent bar shows only the agent picker; a separate “New chat” label is redundant on the dedicated new-chat surface.
- Home composer sends must enter `/home?chat=starting` so the chat panel is mounted to consume the queued seed. The created conversation then becomes the canonical `/home?conv=` route; queued sends must never wait for an unrelated chat surface to mount.
- A successful message fork must navigate to the returned conversation's canonical `/home?conv=` route. Updating only the in-memory active conversation is insufficient because the shell URL is authoritative and can reopen the source conversation.
- People are structured chat references, not prompt-only name strings. Portal teammates resolve through the organization roster and their default User Brain; Slack-only people resolve through the organization-managed person record and Person Brain. A client cannot broaden access by submitting an arbitrary person or Brain id.
- Conversation scope is explicit and editable in the chat header. The saved conversation scope—not merely the currently visible route—drives new messages and agent tool context, so moving a chat does not require navigating away from the current Space.
- Conversation titles appear beside the agent only when chat owns the full workspace **and** the conversation already has a title. Clicking that title renames it. The top bar keeps the page crumb (never the chat name). Untitled and docked headers omit the title entirely (no “New chat” placeholder) so scope and close controls stay clear at narrow widths.
- The shell owns one artifact viewer instead of each feature inventing a modal. Opening an artifact collapses the Files/Tasks/Sources summary panel; opening chat or the summary panel closes the artifact viewer. File swaps preserve the surrounding page and chat.
- The artifact-viewer event adapter is a persistent shell listener, not content conditionally mounted after a target exists. Otherwise the first image-open event has no consumer and cannot create that target. The page remains mounted but removes its forced flex layout while hidden, so the editor replaces rather than joins the Agenda or another work surface.
- A history click publishes its selected row to the canonical chat store before the drawer consumes the pending selection. The conversation panel may merge that canonical row into a stale local page, but it must never consume the pending id by falling back to a different agent or empty conversation.
- The existing Space document editor remains authoritative for Space documents. Images use one shared direct-edit composer in both the Space Media panel and shell viewer; image clicks fall back to the shell studio whenever no mounted Space Media consumer handles the open event.
- Space-backed documents must never be reconstructed as deliverable previews in the shell. The shell adapter resolves the real `space_items` row and mounts `DocEditorPanel` inline; saves use the document's owning Space even when the viewer was opened from chat or another Space.
- Space Media is a browsing surface, not a second chat composer. Its **New image** action opens a fresh docked chat with the current Space/campaign context. A single available viewer destination is rendered as a direct action; the **Open** dropdown is reserved for multiple destinations.
- Open-in provider resolution must remain read-only. Canva design creation starts only from the explicit **Open in Canva** action, avoiding duplicate or abandoned designs when a menu merely opens.
- Direct image edits use the selected image model's multimodal provider route. GPT image edits must not be sent through the Gemini-only SDK adapter, and stale model metadata is merged with the application's known capability map so supported ratios such as Portrait 3:4 do not disappear from the editor.
- Image history and edit persistence follow the source `conversation_id`. **Open in chat** returns to that conversation and deliberately attaches the selected version; merely opening or browsing the image editor does not seed a chat attachment.
- Selecting an image version changes only the active preview and selected outline. The history query is scoped to the source conversation or Space rather than the selected asset, so the rail stays mounted, chronological, and scrollable instead of entering a loading state or moving the selected version to the beginning.
- Expanded media editing is contained inside `ShellWorkspace`, not the browser viewport, so the application rail stays visible. Preview media uses contain sizing and must not force scrolling for portrait or story assets.
- The account-wide artifact library treats docs, campaign artifacts, media, campaigns, and Spaces as independent sources. A failed source does not blank successful results; the page reports failure only when every source is unavailable.
- Generated and uploaded videos remain a first-class artifact category instead of falling into Files. The global and campaign libraries use the playable media URL for a muted preview and preserve that URL when opening the shared viewer.
- The global library uses a bounded set of organization-scoped requests (docs, campaign artifacts, media, campaign labels, and Space labels), never one request per Space.
- The library source control defaults to **Created** so uploaded reference files do not overwhelm agency outputs. **Uploaded** isolates account uploads, while **Everything** combines both origins.
- Account-wide artifact scope combines active-organization records with legacy personal records owned by the signed-in user. Personal rows are always filtered by `user_id`; another member's unassigned records are never included.
