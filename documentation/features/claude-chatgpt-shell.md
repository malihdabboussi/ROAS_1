# Claude/ChatGPT shell (apps/web)

Last Modified: 2026-08-17

## Overview

Dashboard chrome inspired by Claude/ChatGPT and ClickUp: a Simple-by-default combined sidebar for navigation, favorites, Programs, and chat history; an optional Advanced movable workspace rail; a resizable AI chat surface; a Space work dock (no open-item tab strip); a shared artifact slide-out; and a chat-scoped work summary (Connections + Outputs / Sources / Tasks) that sits as a rounded in-flow card when the chat pane is wide and otherwise overlays from the header toggle.

Design reference: `.docs/design/claude-chatgpt-shell-v4/` (HTML prototype + `shell-state.md`).

## Data Flow

1. `useShellStore` (`components/shell/use-shell-store.ts`) owns chat drawer/history widths, page work-area collapse, the shared artifact viewer, right panel, page breadcrumbs, and page header actions. Legacy sidebar pin/peek prefs are cleared so the HQ rail stays icon-only.
2. `DashboardFrame` renders `ShellMenuDockLayout`. Appearance → Menu style persists `simple` or `advanced` in `vibey.shell.menu-style.v1`; Simple is the default. Simple gives the menu and chat the full-height frame with no global bar above them. The breadcrumb, Open in, and Workspace/Portal live in the right work card's own header. While chat is open, **Summary** and **Show page** / **Collapse page** stay in the conversation title bar top-right (the same bar as the chat title) and do not move into the work-card header or the thread. The menu header keeps the ROAS wordmark, global search, collapse, back, and forward controls in one row, followed by New chat, Inbox, Meetings, All Tasks, inline favorites, Programs, More, and the conversation list. `/home` is the New chat surface rather than a separate dashboard destination. Pinned chats sit in a collapsible **Pinned** section above **Recents**; both section labels use the same `hub-menu-section-label` type and hover chevron as Favorites. Recents still owns a constrained flex region with independent vertical scrolling. The account menu is a full-width, divider-separated footer row with the user's name and email. Advanced retains the five-position movable workspace rail and its existing dock preference.
3. Feature pages publish rich breadcrumbs with `ShellBreadcrumb` and optional top-right actions with `ShellHeaderAction`; `ShellTopBar` renders them in place of the path-label fallback. Ancestor crumbs are links or buttons (meeting **Agenda** closes the workspace). Publishers include Team, Spaces, Flows, Skills, agency Clients/Client Campaigns, Programs, and meeting workspaces. `/all-tasks` is named by the path fallback.
4. Top-bar PanelLeft expands/collapses the AI chat drawer (not the HQ menu). The purple control always combines the drawer icon with the **AI Chat** label so the action remains clear in either state; the HQ menu stays icon-led. Click-and-hold directly on the R logo starts menu docking, and releasing nearest a frame edge or the work-card seam commits that placement without adding a permanent drag handle.
   4b. Global Search is the centered top-bar control. Search opens `StudioSearchModal` (⌘K; idle until you type). **AI Chat** is the top-left PanelLeft control: click opens/collapses the drawer.
5. Simple lists actual favorite Programs, campaigns, and Spaces inline rather than linking to a separate Favorites destination. Favorites is the only expandable navigation section. Programs is a single hover destination that opens the full existing Programs tree to the right of the sidebar, independent of any saved Advanced dock preference, and preserves its established row/context actions. More opens only on click and contains Programs, Team, Brain, Projects, Flows, and Artifacts. Hovering Programs lists every program; clicking Programs opens `/programs`. Team/Brain retain their prior nested hover menus. **Recents** owns conversation search, filters, pop-out, and unpinned conversation rows. Pinning a chat moves it into **Pinned** above Recents and keeps `metadata.pinned` through live store merges. The chat drawer never renders a second history selector in Simple mode. Advanced exposes Home, Inbox, Meetings, All Tasks, Delegation Desk, Favorites, Programs, and More. Slack-origin chat rows show a channel badge via `ConversationChannelIcon` / `metadata.source`.

5b. Simple mode treats the shell as three adjacent surfaces: left menu/history, chat, and work/artifact. Each desktop column has an independently persisted, bounded drag width. Opening chat collapses the work card by default. Opening any artifact type uses the same resizable right-side host without replacing chat, and the artifact's existing expand/collapse control can temporarily occupy the full work region. The global top bar retains the page breadcrumb only; workspace/portal/open-in/page-collapse controls render inside the work card. Restore controls render only when a real page target exists, so the shell never shows a disabled duplicate drawer button.
The history list has its own persisted drag width and collapse state. Dragging it fully left or using its collapse control removes the history column entirely while leaving the active chat open. A prominent **Show chat history** control with History + right-arrow icons appears in the chat column header, so the collapsed state never leaves behind a narrow rail or competes with the HQ menu dock. The outer drawer resizes independently and can reach the viewport edge; releasing there enters full-screen chat and preserves the prior docked width for restoration. Search expands from its icon and collapses on outside click. Simple Recents defaults to all of the signed-in user's personal and organization conversations and does not inherit composer agent changes; an explicit agent filter appears as a removable chip beneath **New chat** and changes the real history query. Pixel's default view is unfiltered. 6. Opening a Simple-sidebar history row routes to `/home?conv=` unless that chat last lived on a work surface such as a meeting agenda — then Recents reopens that page beside chat instead of replacing it with full-page chat. An explicit history selection still releases previously attached meeting context when switching to a different conversation. Recents defaults to logo identity: Slack/Telegram channel marks, a calendar for meetings, and no generic identity dot. Activity overlays the Slack/Telegram/meeting logo when present; rows without a logo keep the standalone left-edge unread/working/action dot. Meeting titles still omit the redundant legacy `Meeting —` prefix. Duplicate active rows carrying the same `meeting_item_id` collapse to the newest conversation. `/home` alone is the clean New chat state, while nested tools such as `/home/inbox`, `/home/meetings`, and `/all-tasks` remain page workspaces. `/home?chat=starting` bridges submission until the canonical conversation id exists. Workspace routes can still use the docked drawer. 7. Open in ▾ resolves Drive / Google Docs / Canva targets from the focused space `?item=` (and optional media focus). Canva targets are lazy: the shell does not generate or import a design until the user selects Canva. 8. The summary panel opens from the chat header (list icon grouped with **Show page** in the top-right). When the chat pane is at least 1024px wide it sits in-flow as the same rounded overlay card, inset from the chat edges, with no full-height divider, and auto-opens; narrower panes stay closed until the header toggle, which overlays the thread. Empty Outputs / Sources / Tasks / Connections start collapsed. Loading rows use a skeleton rather than a Loading label. With an active chat it also shows a **Connections** section above Outputs so General chats can attach or change campaign/Space without a header chip. The add control opens the click-stable `ConversationScopePicker` (programs first, searchable clients, General pinned). Without an active conversation id, only the personal Tasks queue is available. 9. Campaign / Space scope for a conversation is edited in Connections. Pixel may suggest a link from `suggestedWorkContext`; it does not auto-apply route or page context onto an already-open conversation. Selecting another Space atomically retargets the conversation and future agent work; selecting **General** clears the Space while leaving the visible workspace open. New Chat **Choose Space** uses the same click-stable picker instead of the composer plus-menu hover submenu. 10. Chat presentation is mode-aware: full chat can show an inline-renamable title beside the agent when a title exists; docked and untitled chats omit the title (no “New chat” placeholder). Empty New chat has no breadcrumb; once a conversation is active, the shell breadcrumb resolves its chat title. Successful-turn persistence may reaffirm a temporary first-message title, but it must not overwrite a concise generated title that has already arrived. 11. Submitting the Home new-chat composer records and clears any prior active conversation, queues the message with `railIntent: 'new'`, mounts the full chat at `/home?chat=starting`, then replaces that temporary URL with `/home?conv=` only after a different, newly created conversation becomes active. 12. Artifact chips, chat outputs, Space artifact/media cards, Brain source previews, Space document visuals, and the Outputs summary tab publish the shared `@/lib/artifacts` shell-viewer target. Every chat artifact type resolves through one typed card-to-destination contract, so compact final-output rows and rich inline cards open the same canonical component. A new final output opens that viewer while the agent is working; historical outputs remain user-opened. Entity cards open their matching artifact preview, Space documents and custom objects open the Space editor, documents open the document host, presentations and funnels open their FullMode editors, tasks open task detail, missions navigate to `/home?mission=`, and flows navigate to `/flows?flow_id=`. The shell opens one resizable right-side viewer that defaults to an editor-sized column (~880px, 960px for docs/decks/funnels), has a 420px minimum and no maximum so it can fill the row, swaps content in place, and closes it on top-level navigation. Path crumbs (`Artifacts / files / title`) stay in that same right pane: Artifacts opens the account library, files opens conversation files or the Files filter, and the title returns to the open editor. 13. Space-backed document targets load the real Space item into the canonical document editor's inline mode, including the owning Space's fields, Doc/Visual views, fixed rich-text toolbar, grouped Copy/download actions, Google Docs export, settings/share controls, and autosave route. The shared viewer can expand that same editor to full screen without swapping renderers. Generic documents and files without a Space item continue to use the read-only deliverable renderer. **Open in Space** launches the same document in its full Space destination. Task-detail Space and view crumbs navigate to the owning `/spaces?space=` route and exact `v` view instead of rendering as inert location labels. Image and video targets open the shared media studio from chat, Campaign, and Space surfaces. Open events carry media kind + optional URL; after `getAsset` the viewer corrects `type` from `asset_type` so MP4s never render as `<img>`. The history rail lists conversation/Space images and videos together. Image edits use the multimodal image route for GPT and Gemini, support one or more reference images, preserve the source ratio (including 4:5 static ads), expose Square / Portrait ad / Portrait / Story / Landscape / Widescreen actions in the top toolbar, and save every edit back to the source conversation. The editor keeps a fixed, scrollable conversation timeline with the selected version highlighted, fits tall images inside the viewport, and provides a floating prompt composer with reference uploads and voice transcription. It downloads the actual file, exposes **Add to chat** as a direct action that attaches the selected version without dismissing the studio, and keeps **Open in new tab** / **Open in Canva** in the overflow menu. Opening or browsing media never attaches it automatically. 14. `/artifacts` is the account-wide artifact library. It paginates through docs and media, merges every campaign-artifact family from the active organization plus personal legacy assets owned by the signed-in user, labels each row with its campaign or Space, and opens rows in the shared viewer. Uploaded assets are hidden by default and available through the source filter. Type filters include Docs, Images, Videos, Sheets, Presentations, Funnels, Campaign assets, and Files. Video rows and cards render a muted first-frame preview and open in the shared video viewer. More → Artifacts links here; Space-specific views remain inside their Space. 15. Forking an assistant turn creates a new conversation with the original messages through that turn, adds it to chat state, and navigates to the canonical `/home?conv=` URL for the returned fork id. The success toast is shown only after creation succeeds. 16. Every shared Chat composer can attach a person from the `@` menu or the plus menu. **People** combines active portal teammates with Slack-only managed people in the active organization. The server validates the selected identity, resolves its managed Person Brain or canonical User Brain, and adds that durable person context to the agent turn. The Home composer loads People even when no campaign is selected. 17. Home / New chat uses the standard composer with an inset shelf beneath it for Choose Space and Plugins only — no Try-tip banner and no Mission/Offer/artifact chips above the input. Active chats show a rotating idle Try-tip catalog above the composer; closing a tip hides the banner in that chat. Create actions stay in the + Create menu; selecting one still seeds the visible request and attaches a hidden routing contract that names the matching read/write actions, requires a successful tool receipt before claiming completion, and remains active only while the seeded request prefix is intact. 18. Home layout preference version 3 re-seeds old local and server layouts once to full-width Agenda + a two-row-tall Inbox. Customize mode supports independent 1/2-column width and 1/2/3-row height controls for every card, and the Home canvas scrolls through the full configured layout. Users can still customize the dashboard and add the lazy-loaded Ask Pixel composer. 19. Inbox reads `user_notifications` through the dedicated missions-notifications controller. `inbox_bucket`, `snoozed_until`, and `cleared_at` stay independent from `read_at`; one RPC returns unread counts for Primary / Other / Later / Cleared. Inserts are classified by type, realtime inserts use the same client predicate, and clear/snooze/move/read actions update optimistically with rollback. Automated import, sync, and completion notices are projected into a separate **System** lane instead of competing with work that needs a decision; the Primary count excludes that virtual lane. 20. Inbox, Meetings, and All Tasks use full-page presentations on their dedicated routes. Inbox uses a responsive list/detail workspace: selecting a row marks it read and keeps its full context plus triage actions visible at the top, approval notices resolve their source mission's current status, and stale approvals are labeled **Resolved**. Native task details replace the current right-side work page rather than opening over AI Chat; **View source** still navigates to the originating Space, Mission Control item, DM, or integration. Search, mark-all-read, and clear-current-view actions support fast queue triage. Shared selectors render the selected label instead of an empty native-looking control, Inbox dates reserve a stable column so rows align, and chevrons remain vertically centered with their rows. All Tasks keeps the rollup list mounted and opens canonical task detail in a right-side panel. It defaults to every open task, with an Assigned to me filter rather than a My Tasks screen. `/home/my-tasks` redirects there. Expanding the Home dashboard My Tasks card opens All Tasks filtered to assigned work instead of a separate overlay. 21. Chat-history filters render in a body portal so shell flyouts cannot cover or clip them. The Chats and Tasks work page opens a selected conversation in the left drawer without navigating back to Home or closing the work page. 22. Team agent detail uses the canonical AI Chat drawer instead of rendering a second agent-chat runtime. Entering an agent selects that agent, opens a blank canonical chat, expands the history rail, filters history to that agent, and keeps the Team surface attached as visible removable context. The full agent grid remains in the work area while the selected agent profile opens in its right-side detail panel. 23. The page expand/contract control renders only when chat has actually created a collapsible page relationship or the page is currently hidden. A full-page Home conversation has no close-chat action; navigation happens through New chat, history, and the shell destinations. The outer work-area wrapper is the only reveal-transition owner: it clips one right-anchored page surface, while the inner page has no second transform or animation. 24. Campaign/Space attachment is edited in Connections, Recents Filter, and Choose Space. The composer does not show a removable context chip for that attachment. 25. The default Pixel empty state shows only Pixel's name and capabilities; it does not render an organization-role subtitle. The agent picker keeps Pixel first, followed by a labeled **Other agents** section. 26. Selecting a history row writes that exact conversation into the canonical chat store before opening the drawer. In Simple mode, every history row routes to the full `/home?conv=` chat from any current page instead of opening the legacy drawer in place. The mounted chat panel waits until the selected row is resolvable, merges it into its local list, and then selects the conversation and its saved agent. The shell artifact-viewer adapter remains mounted while hidden so image-open events from either the inline preview or output card can create the first viewer target. On a desktop full-Home conversation, that target opens as a constrained third column beside chat and temporarily replaces Outputs / Sources / Tasks; on ordinary page workspaces and mobile, it temporarily replaces the page work area. Closing it restores the same page state and reopens the conversation summary. Remembered work surfaces carry identifying query params (`conv`, `meeting`, `space`) while transient `chat`/`surface` params are dropped; meeting restores use `/home/meetings?meeting=` and resolve from the in-flight payload or agenda cache. 27. Empty chats render agent selection once in the centered identity. Its chevron appears on hover and opens the agent roster. Established conversations retain the header picker because the centered identity is no longer present. The full Chats and Tasks page aligns its compact heading with the conversation list and shows updated dates plus row dividers without an extra rule beneath the page header. 28. Established chat composers place the model selector beside the voice/send controls and render context usage as a compact segmented line beneath send. New, conversation-less composers omit the meter entirely so context chrome appears only after a chat has started. 29. The work summary uses the same rounded overlay card on every width. When the pane is wide enough the card sits in-flow on the right, inset from the chat edges, with no full-height divider; otherwise it drops from the header toggle. Connections, Outputs, Sources, and Tasks stack as collapsible sections (empty ones start closed). The create (+) catalog swaps the card body in place, and meeting-scoped chats show an **Open meeting workspace** row routing to `/home/meetings?meeting=<call item id>`. Space media listeners no longer consume the shared media-open event, so generated-image cards can continue into the persistent shell viewer. 30. Every chat-history row resolves one per-user activity state with fixed priority: amber **Needs your action**, animated purple **Working**, blue **New activity**, then no indicator for read/idle. Opening a conversation records its read timestamp immediately; a background stream that completes while another conversation is selected becomes unread without waiting for a feed refresh. 31. Image viewer **Markup** mode records pen paths and pins as normalized image coordinates. Each mark owns separately saved feedback, remains selectable in the top tool strip, and can be deleted independently. The feedback card can be dragged between canvas corners so it does not obscure the target. **Regenerate with edits** is a separate top-level action and converts all feedback-complete marks into strict location-specific edit instructions before using the existing image-edit stream. The source remains unchanged; the generated result is registered and retained as a new media version in the history rail. 32. Full Home new chat surfaces up to three **Suggested next moves** directly beneath the shared standard chat composer. `GET /api/home/next-moves` reads canonical Meetings `follow_up` Space items and keeps only the signed-in user's own actions plus unassigned follow-ups from meetings they actually attended (calendar invitees, participant emails, Fathom attendee tags, or recording attendees). Teammate-owned follow-ups from other people's calls are excluded, even when those recordings live in a shared org Meetings space. It then excludes per-user snoozed rows and returns source-aware draft prompts. Selecting a suggestion fills the composer for review without sending it. Snooze hides it for seven days, while Dismiss uses the existing Home recommendation dismissal store for a durable hide. 33. Shell page roots and the Simple sidebar use one `h-full` / `min-h-0` / constrained-flex ownership chain. Inbox, meeting pages, and other page bodies own their vertical overflow, while Recents scrolls independently above the pinned account footer. 34. Pixel and other authorized agents can use the read-only `search_conversations` action when a user refers to another chat. The action searches active conversation titles inside the resolved user and organization scope and returns bounded recent user/assistant excerpts, summaries, and conversation ids. It must be attempted before asking the user to reconstruct accessible chat history. 35. Simple chat always keeps **Summary** then **Show page** / **Collapse page** in the conversation title bar top-right, whether the page is open, collapsed, or the surface is `/home?conv=`. They do not float in the thread, jump to the work-card header, or disappear after opening or closing the summary. `/home?conv=` does not stack a Simple work-card header above that title bar; Show page there opens the drawer for the current chat and restores the last real work page. `/home` is recorded as **Home**, never as a blank hover-history row. 36. Meeting workspaces derive a deterministic conversation UUID from the meeting item id. Concurrent workspace hydration or start requests therefore upsert the same chat instead of creating parallel Recents rows. Opening a linked meeting also archives any older unlinked conversations with the same user, organization, and meeting metadata; the linked conversation remains active and the archived copies remain recoverable. 37. Navigation between left-sidebar screens is chat-preserving. `ShellWorkspace` resolves the target through `shell-screen-chat.config.ts`: an open drawer conversation is kept, while a dismissible prompt offers the target screen's different remembered chat. An open pane without a conversation starts fresh instead of restoring unrelated history. Conversations are remembered per screen in `vibey.shell.v1`; Space, Campaign, and channel routes retain their existing scoped chat hosts.

# Claude/ChatGPT shell (apps/web)

Last Modified: 2026-08-17

## Overview

Dashboard chrome inspired by Claude/ChatGPT and ClickUp: top bar with centered Search ⌘K and a top-left PanelLeft control for AI Chats, icon-rail HQ sidebar (always collapsed), a resizable left AI drawer with chat history, a Space work dock (no open-item tab strip), a shared artifact slide-out, and a chat-scoped summary panel (Connections + Outputs / Sources / Tasks) opened from the chat header.
