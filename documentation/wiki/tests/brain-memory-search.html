✅ Memory in, search out

Last updated: 2026-09-10 Category: Tests and checks Linear: ROA-9 Source of truth: local run on 2026-09-10 00:24 local, log /tmp/roas-agent-api.log

Proves the personal-memory door and the search road together, with no clicking: a sentence goes in through the api's "remember" endpoint, Atlas stores it as a memory with an embedding, then the api's search endpoint finds it by meaning. About 20 seconds on a fully local stack. Pairs with the textbook import test, which covers the other door.

📍 Paths starting with brain/ mean apps/api/src/modules/brain/.

1 Preconditions

  • Same as the textbook test: your own database and Redis, api on 3001, agent-api on 3003, gateway on 18789, Gemini key in apps/api/.env.
  • A login token for the test user. No password needed: ask the local auth admin API for a magic link and exchange it for a session. Keep the token in a scratch file, never in chat.
📍 Token: POST /auth/v1/admin/generate_link with the service key and type: magiclink → hashed_token → POST /auth/v1/verify with the anon key and type: magiclink, token_hash → access_token. The api verifies it against the local project's keys: brain/guards/brain-auth.guard.ts.

2 Steps

  1. Prove the token: GET /api/brain/health with Authorization: Bearer returns 200 and the brain counters.
  2. Remember one distinctive sentence: 
    POST /api/brain/remember
{"content": "…", "source_type": "document", "source_title": "Lead magnet note"}
    Response: {"success": true, "jobId": "…", "status": "queued"}.
  3. Watch the job reach succeeded within about 20 seconds, then read the newest ns_memories row: a memory_type, source_type = document, and embedding is not null.
  4. Search by meaning, with a question that does not reuse the sentence's words: 
    GET /api/brain/search?q=which%20lead%20magnet%20converts%20best&limit=3
    Expect the new memory first with a score above about 0.7.

4 Things to watch

  • Counters disagree. After the run, health reported total_memories: 1 but memory_counts_by_type: {}. Two different queries feed those numbers. Worth a small ticket.
  • Search needs the embedding. A memory created without one, for example through the api's direct create path, will never be found by meaning. See Problem 3 on the Brain page.
  • This is not the chat door. The helper in chat still fails to save memories (ROA-29). This test proves the storage and search roads are healthy, which narrows ROA-29 to the agent's instructions.
