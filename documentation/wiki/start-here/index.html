🚀 Start here

Last updated: 2026-09-10 Category: Start here Source of truth: package.json, apps/*/package.json, apps/*/.env.example, AGENTS.md, CLAUDE.md

ROAS is an agent-driven marketing and operations platform. It is one big repository holding several apps that talk to each other. This page tells you what those apps are, what you need before starting, the exact commands to start them, the config each one needs, and the rules everyone follows.

2 What you need before starting

💻 On your machine

  • Node 22 and pnpm 9.15.4. The repo pins the pnpm version.
  • Redis running on localhost:6379, and it must be your own. Never point a local api at a shared or cloud Redis: any other api attached to the same Redis will grab your jobs and run them elsewhere, and your terminals will show nothing. Seen live on 2026-09-09, see the Brain page, Live finding 2.
  • Git and a GitHub login for pull requests.
📍 package.json engines.node >=20, packageManager pnpm@9.15.4 · Redis default noted in AGENTS.md "Cursor Cloud specific instructions" · queue names in apps/api/src/modules/agent-runtime/agent-runtime-queues.ts

🔑 Accounts and keys, not in the repo

  • Your own Supabase database. Since 2026-09-10 a local Supabase is wired: supabase/config.toml exists, see section 7 below. Do not develop against the shared dev project sicxiwyukxtqicevlwuc: a cloud api is attached to it and will take your jobs. Never point local writes at production lhfgtsjetcardinpgouq.
  • An LLM key. OPENROUTER_API_KEY in apps/api/.env; the agent scripts read it from there. GEMINI_API_KEY for brain embeddings and OCR.
  • One shared secret: VAULT_ENCRYPTION_KEY must be byte-identical in apps/api/.env and apps/agent-api/.env, or stored tokens cannot be read.
📍 supabase/config.toml (migrations and seed disabled, restore-based) · dev:agentapi script in root package.json reads OPENROUTER_API_KEY from apps/api/.env · vault note in apps/agent-api/.env.example:13-15

3 First-time setup, step by step

Step 1. Install everything once.

pnpm install

Step 2. Create the config files. Each app has an example file. Copy it and fill in the values you have.

cp apps/web/.env.example apps/web/.env.local
cp apps/api/.env.example apps/api/.env
cp apps/agent-api/.env.example apps/agent-api/.env
cp apps/openclaw/.env.example apps/openclaw/.env
cp apps/mission-worker/.env.example apps/mission-worker/.env

Step 3. Check the configs agree with each other. Two helper scripts exist for ROAS. The first copies shared values into the agent config. The second fails if any app still points at the old Vibey database.

bash scripts/roas/sync-local-agent-env.sh
bash scripts/roas/verify-local-env-alignment.sh

Step 4. Start Redis in its own terminal. It is a separate server program, already installed on the Mac, and nothing in the repo starts it for you.

redis-server

Step 5. Start the apps you need, each in its own terminal, in this order. The API first because the web app and the agent call it.

pnpm dev:back        # api on 3001
pnpm dev:app         # web on 3000
pnpm dev:agentapi    # agent-api on 3003, only if you need chat or agents
pnpm dev:agent       # openclaw gateway on 18789, only if you need agents to run

Step 6. Open http://localhost:3000. With placeholder Supabase values the login page renders and the home page redirects to login. With a real project you can log in.

6 Rules everyone follows

🌿 Branches and shipping

  • Never work directly on main. Make a branch, open a pull request, get it reviewed.
  • Shipping stops at the pull request. Going live is a manual merge or a manual script.
  • Docs and changelog are written before the commit, not after.
  • On every commit a hook runs the architecture size check and the linter on staged files.
📍 AGENTS.md §0 · .claude/rules/git-workflow.md · hook .husky/pre-commit runs pnpm architecture:check -- --staged and pnpm lint-staged

🧪 Testing

  • Browser tests attach to a running app. They never start servers on their own.
  • Tests against anything that is not your own machine are read-only.
  • Every acceptance rule needs a clear "how do we know it passed".
  • Full workflows on the Tests and checks page.

7 Your own local database, step by step

Copy the shared dev database onto your laptop once, then every job, log, and row is yours. Done for the first time on 2026-09-09/10; about 30 minutes.

  1. Tools. Docker Desktop running, brew install supabase/tap/supabase, Postgres client tools 16+. Node 22 or 23 from nvm for the apps.
  2. Start local Supabase from the repo root. Migrations and seed are off in supabase/config.toml because we restore a real copy instead of replaying 937 files. 
    supabase start -x edge-runtime,logflare,vector,imgproxy
    Database on 54322, API on 54321, console on 54323. Keys are the standard local ones printed by supabase status.
  3. Vector extension in public. The dev database has it there, and the dump types columns as public.vector. Putting it under extensions makes 15 tables fail. 
    psql postgresql://postgres:postgres@127.0.0.1:54322/postgres -c "create extension vector with schema public; create extension pg_trgm with schema extensions;"
  4. Dump the dev database in pgAdmin: format Custom, whole database is fine. The file is made by Postgres 17 tools, so restore with the tools inside the container.
  5. Restore, auth first then public, because profile rows point at auth users: 
    docker cp ~/backup.dump supabase_db_roas-local:/tmp/backup.dump
docker exec supabase_db_roas-local pg_restore --data-only --no-owner -n auth -t users -t identities -d postgresql://postgres:postgres@127.0.0.1:5432/postgres /tmp/backup.dump
docker exec supabase_db_roas-local pg_restore --no-owner -n public -d postgresql://postgres:postgres@127.0.0.1:5432/postgres /tmp/backup.dump
    If identities fail on a foreign key, run the identities line again after users landed. Expect zero errors on the public restore.
  6. Turn off cloud routing on your profile, or the api sends your jobs to a cloud runtime: 
    update profiles set agent_runtime_type='fly_machine', agent_runtime_url=null where id='<your user id>';
  7. Point the apps at it. In apps/api/.env: SUPABASE_URL=http://127.0.0.1:54321, the local anon key, service role key, and JWT secret; REDIS_URL=redis://localhost:6379; PORT=3001. In apps/web/.env.local: the two NEXT_PUBLIC_SUPABASE_* values. Create apps/agent-api/.env with PORT=3003 so it stops borrowing the api's port.
  8. Restart api, web, agent-api. Log in again with the same password; it carried over. Run the textbook import test to prove it.

? Questions people asked

How do I start Redis? Is it pnpm --filter @vibey/queue-worker dev? 2026-09-09
No. Redis is a separate server program, not one of the apps. Start it in its own terminal with redis-server (installed at /usr/local/bin/redis-server, Redis 7). The queue-worker is an app that uses Redis; it needs its own apps/queue-worker/.env with the Supabase values and fails with "Missing SUPABASE_URL" without it. For brain work you do not need the worker at all: the brain import queue is processed inside the api. 📍 apps/api/src/modules/brain/services/brain-import-runtime.processor.ts:14 @Processor(AGENT_RUNTIME_BRAIN_IMPORT_QUEUE) · worker error source apps/queue-worker/src/modules/logger/error-reporter.ts:110
