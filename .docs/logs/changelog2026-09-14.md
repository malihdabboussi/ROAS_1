# Changelog - September 14, 2026

## [2026-09-14 01:20] - [FEATURE]
What: ROA-40 Phase 0. Added the provider-agnostic transcript contract (`TranscriptSourceEvent`, `TranscriptProvider` with optional push/pull/hooks capability groups, `MeetingProviderRegistry`), one shared webhook door `POST /api/integrations/meetings/webhooks/:provider/:connectionKey` with per-connection keys and a replay table, and `MeetingIntakeService` which fans a normalized meeting out to the brain import, the customer-brain outbox and the Meetings space. Fathom now runs as an adapter: Standard Webhooks HMAC verification (`webhook-id`/`webhook-timestamp`/`webhook-signature`, 5-minute window), transcript and action-item hydration, agenda-exclusion and alias-capture hooks, Page Grader and Campaign Brain routing. OAuth connect registers the new door; an internal route plus `scripts/roas/reregister-fathom-webhooks.sh` migrate existing connections. The legacy `POST /api/integrations/fathom/webhook` now only resolves the owner and delegates to the intake.
Why: ROA-40 asks for one system any note taker can join; the Fathom-only pipeline had no verifiable signature check and no seam for a second provider.
Impact: Fathom deliveries to the new door are rejected unless correctly signed. Existing connections keep working through the legacy door until re-registered. `fathom-envelope.adapter.ts` replaced by `meetings/providers/transcript-envelope.ts`. `INTERACTION_CHANNELS` gains `fireflies` and `read_ai`. New migration `20260914090000_meeting_webhook_deliveries.sql` (replay table, webhook-key index, provider CHECK widened). 233 API tests pass in the meetings and Fathom suites.
