## [2026-09-14 01:20] - [FEATURE]
What: ROA-40 Phase 0. Added the provider-agnostic transcript contract (`TranscriptSourceEvent`, `TranscriptProvider` with optional push/pull/hooks capability groups, `MeetingProviderRegistry`), one shared webhook door `POST /api/integrations/meetings/webhooks/:provider/:connectionKey` with per-connection keys and a replay table, and `MeetingIntakeService` which fans a normalized meeting out to the brain import, the customer-brain outbox and the Meetings space. Fathom now runs as an adapter: Standard Webhooks HMAC verification (`webhook-id`/`webhook-timestamp`/`webhook-signature`, 5-minute window), transcript and action-item hydration, agenda-exclusion and alias-capture hooks, Page Grader and Campaign Brain routing. Why: ROA-40 asks for one system any note taker can join; the Fathom-only pipeline had no verifiable signature check and no seam for a second provider.
Impact: Fathom deliveries to the new door are rejected unless correctly signed. Existing connections keep working through the legacy door until re-registered. `fathom-envelope.adapter.ts` replaced by `meetings/providers/transcript-envelope.ts`. `INTERACTION_CHANNELS` gains `fireflies` and `read_ai`. New migration `20260914090000_meeting_webhook_deliveries.sql` (replay table, webhook-key index, provider CHECK widened). 233 API tests pass in the meetings and Fathom suites.

## [2026-09-14 02:27] - [FEATURE]
What: ROA-40 Phase 1. One provider-agnostic brain job, `meeting_transcript_import` (and `campaign_meeting_import`), whose payload carries the normalized transcript so Atlas always receives the text; `buildMeetingMissionInput` produces the Atlas input for any provider. New manual import route `POST /api/integrations/meetings/:provider/import` and `GET /api/integrations/meetings/providers` (capabilities + connected flag). Fireflies becomes an adapter: `Transcription completed` ping verified with `x-hub-signature` (hex or base64), transcript fetched via GraphQL before enqueue, action items parsed from the formatted block, `listRecent` with a skip cursor. Fireflies connect accepts an optional webhook signing secret (vault label `webhook_secret`), issues a stable per-connection webhook key, and status returns `webhookUrl`/`webhookConfigured`; `POST /api/integrations/fireflies/webhook-secret` sets the secret later. Web: Fireflies catalog row gains API key + signing secret fields, the Manage row shows the address to paste into Fireflies, and Fireflies imports (brain and campaign) call the shared import route. Cross-pollination and the brain queue lists recognize the new job types.
Why: Fireflies brain imports previously reached Atlas with only a transcript id (no text); every provider needed its own job type and enqueue path.
Impact: Fireflies imports now contain the transcript. Fathom webhook intake also queues the generic job. Legacy `fathom_meeting_import`/`fireflies_transcript_import` routes remain for callers not yet moved (Phase 4). 415 API tests pass across meetings, Fathom, Fireflies and brain suites; the one failure (`type-c-services.characterization.test.ts`, Slack observation module) fails identically on the branch before this change. Web typecheck: 18 pre-existing errors, none in touched files.
