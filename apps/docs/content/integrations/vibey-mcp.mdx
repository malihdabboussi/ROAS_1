ROAS has its own MCP server at **`https://mcp.roas.io`**. Add it to your favorite AI tool — Claude, ChatGPT, Cursor, and others — and that tool can work with your ROAS workspace directly.

This means you can sit in Claude and ask it to search your Company Brain, save a memory, create a campaign, or kick off a mission — and it all lands in ROAS, exactly as if you'd done it in the app.

<Callout type="info">
  Looking for the opposite — connecting outside tools *into* your ROAS agents? That's covered in
  [MCP Servers](/integrations/mcp-servers).
</Callout>

## What You Can Do

Once connected, your AI tool can:

| Area               | What it can do                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| **The Brain**      | Search your Personal, Company, Customer, and Agent Brains, and save new memories and knowledge  |
| **Documents**      | Read, search, and save documents in your Spaces, including downloadable Word docs               |
| **Spaces & Tasks** | Browse your Spaces, views, items, and tasks                                                     |
| **Campaigns**      | View your campaigns and create new ones                                                         |
| **Marketing**      | View and create funnels, websites, pages, and email sequences                                   |
| **Missions**       | Launch missions, inspect their plans and subtasks, follow logs, and verify durable deliverables |
| **Agent Skills**   | View your agents' skills and teach them new ones                                                |

## What It Will Never Do

The ROAS MCP only exposes safe actions. It can read and create — it cannot destroy:

- ❌ No deleting anything
- ❌ No publishing pages or sending emails
- ❌ No billing or account changes

Every action also runs through the same permission checks as the ROAS app itself, so a connected tool can never do more than you can.

## Connecting

The address is the same everywhere: `https://mcp.roas.io`

## Claude Missions Plugin

The repository also contains the **ROAS Missions** Claude plugin. It bundles the hosted connector with two reusable skills: a general mission runner and the Pixel Ladder 1–30 validation runbook.

For an organization-managed install, add the `dylanvanas1/roas-platform` GitHub repository under **Organization settings → Plugins → Add plugins → GitHub**, enable **ROAS Missions**, and authenticate the `roas-platform` connector when Claude asks. The repository marketplace manifest is `.claude-plugin/marketplace.json`; the plugin is stored in `plugins/roas-missions`.

The mission workflow does not treat a launch receipt as completion. Claude follows the mission id through `get_mission`, `get_mission_plan`, `list_mission_subtasks`, `get_mission_logs`, and `get_mission_deliverables`, then reports the observed state and evidence. Human approval gates remain human decisions.

Try: _"Run the Pixel Ladder test runbook, classify blocked items first, and show PASS, FAIL, or BLOCKED evidence for every requested check."_

<Callout type="tip">
  Any other app that supports remote MCP servers works too — just give it the address
  `https://mcp.roas.io` and sign in when asked.
</Callout>

## The Approval Screen

The first time a tool connects, ROAS shows you an approval screen before anything happens. This is where you stay in control:

1. **Choose the account** — your personal account or one of your organizations. The tool only sees that account's data.
2. **Set permissions per area** — for each area (Personal Brain, Campaigns, Marketing, and so on), choose **None**, **Read**, or **Write**. Want Claude to read your Brain but never change it? Set it to Read.
3. **Click Allow** — the tool is connected with exactly the access you granted, nothing more.

If you connect through an organization, your role there caps what you can grant — viewers can only grant read access, while owners and admins can grant everything.

## Built-In Guidance

The ROAS MCP doesn't just hand over tools — it teaches the connected AI how to use them well:

- Every connected tool receives instructions explaining what's safe, what each permission means, and how to call ROAS correctly.
- A built-in **docs search** tool lets the AI look up these very docs before acting, so it answers questions about ROAS accurately.
- A **describe action** tool lets the AI check exactly what an action needs before calling it, so fewer things go wrong.

The hosted endpoint follows MCP Streamable HTTP response semantics: JSON-RPC requests return
`200 OK`, while accepted notifications return `202 Accepted` without a response body. This keeps
the same connector interoperable across Claude and other remote MCP clients.

The **General** workspace shown in ROAS is a system campaign. To browse its Spaces, the connected
AI lists accessible campaigns, selects the unique campaign whose `config.system_kind` is
`"general"`, then calls `list_spaces` with that campaign id. The separate `general: true` filter
means uncampaigned Spaces where `campaign_id` is null; it does not mean the General workspace.

Direct Personal Brain memories use one of these types: `decision`, `insight`, `preference`, `fact`,
`story`, `framework`, or `event`. Invalid types are rejected before a write. If any MCP tool fails,
the friendly explanation and the complete structured error contract are returned in model-visible
text as well as `structuredContent`, so the connected AI can correct its payload or stop retrying.
