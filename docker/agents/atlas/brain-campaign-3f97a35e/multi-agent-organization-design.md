## Context

Building a multi-agent AI organization isn't just about plugging in tools — it requires the same design thinking as a real company: hierarchy, role clarity, knowledge access control, and iterative team development.

## Core insight

Managers and workers need fundamentally different knowledge. Getting this wrong creates a bottleneck; getting it right creates compounding automation.

## The story

**Knowledge Access Control Principle:** In a multi-agent setup, knowledge should be domain-tagged and role-scoped. Manager agents need: what result you're trying to achieve, the purpose behind that result, and the strategy to get there. Worker agents need: the offers, target avatars, brand theme/voice/values, brand colors, and asset libraries. A copywriter agent doesn't need the company's growth strategy; a CEO agent doesn't need the hex codes. Mixing these creates noise and reduces output quality.

**Agent Hierarchy Evolution (Sefy's experience):** Started with 1 agent, grew to 3, then 8 — which became overwhelming to manage. Solution: appointed one agent as CEO with full autonomy to delegate. Initially a 'total disaster' — the CEO tried to do everything herself. Through iterative instruction changes (essentially mentoring), the CEO learned to delegate properly and the system started working. Key lesson: treat agent development like onboarding a new hire, not programming a machine.

**Personality Improves Output:** When building the multi-agent team, Sefy tested implementing personality traits within role descriptions — not just task specs but actual character. Result: measurably better outputs. Agents became more consistent, more predictable, and produced higher-quality work. The personality shapes HOW the agent interprets its role, not just WHAT it does.

**The Train-Once-Use-Forever Pattern:** Agent skills create compounding automation. First time you ask for a proposal PDF, it may be rough. You give feedback ('structure it 1, 2, 3, 4') and ask the agent to 'create a skill to create proposals.' From that point on, every proposal follows the same structure — no re-training needed. The initial investment in defining a skill pays dividends permanently.

**Vibey's Flywheel:** Product usage generates meetings. Meetings (via Fathom integration) feed the brain. The brain improves agent performance. Better agents drive more usage. The system compounds itself.

## Key takeaways

- Manager knowledge: strategy, purpose, desired outcome
- Worker knowledge: offer details, avatar, brand voice, visual guidelines
- Add personality to agent roles — it measurably improves output quality and consistency
- CEO agent development requires mentoring, not just configuration
- Build skills for repeatable tasks — the train-once pattern is the compounding multiplier
- Fathom over Firefly for brain ingestion: auto-syncs without manual action
