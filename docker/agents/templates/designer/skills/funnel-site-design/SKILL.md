# Funnel and Site Design

Own the design decisions that make a marketing page feel specific, credible, and professionally art-directed. Builders own implementation. `roas-funnel-design` and `funnel-wireframe` own structural wireframes. This skill owns the high-fidelity step between them.

Read these references as needed:

- Read `references/design-contract.md` before creating art direction.
- Read `references/brand-register.md` for a new build or substantial redesign.
- Read `references/visual-critique.md` when reviewing an implemented preview.

## Design principles

Ground every choice in the real subject. The offer, audience, proof, product, founder, place, process, and assets provide a richer visual vocabulary than generic industry aesthetics.

Choose one visual thesis. A page becomes memorable through a coherent point of view, not through the number of effects it contains. Spend boldness on one signature element and keep the surrounding system disciplined.

Treat structure as information. Cards, labels, numbers, icons, dividers, and motion should clarify real relationships. If they are only decoration, remove them.

Use real evidence. Do not invent urgency, scarcity, testimonials, customer counts, awards, logos, or performance claims. A credible quiet page converts better than fabricated proof.

Design mobile as a composition. Decide what leads, what changes order, what becomes compact, and which action stays reachable at 390px. Do not describe mobile as "stack everything."

## Workflow

### 1. Establish the brief

Identify:

- surface: funnel, landing page, or multi-page website
- audience and the page's single job
- offer and verified proof
- existing brand tokens, fonts, assets, and components
- real content and missing assets
- anti-references: visual directions the user rejects
- technical constraints and target builder

If one missing fact would materially change the direction, ask one focused question and recommend a default. Otherwise state reasonable assumptions and continue.

### 2. Find the subject-specific direction

Write one sentence describing the page in a way a direct competitor could not reuse unchanged. If the sentence still fits most businesses in the category, the direction is generic; derive it again from the subject's materials, language, behavior, or proof.

Choose:

- a visual thesis
- one signature element
- a typography relationship
- a restrained color strategy
- a composition and section rhythm
- an image or asset strategy
- a motion posture: none, restrained, or expressive, with a reason

Do not default to gradient text, floating blobs, glass cards, bento grids, oversized metric rows, icon tiles, badge-pill heroes, decorative grids, or fade-up animation. Any of them may be valid when the brief genuinely calls for it; none is a default.

### 3. Produce the Design Contract

Follow `references/design-contract.md`. Make the contract decisive enough that a builder can implement it without inventing a second design direction.

Include explicit desktop and mobile composition. Name the real assets to use or produce. Mark every unverified proof item as missing rather than fabricating it.

Label substantive decisions as Confirmed, Proposed, or Missing. A useful proposal is not approval: do not present a fallback font, invented token value, copy line, or arbitrary layout ratio as production-ready merely because the builder needs direction.

Keep the contract edited enough that a builder can scan it in under five minutes. State the shared system once, avoid repeating the brief or proof rules in every section, and spend detail on decisions that materially change implementation.

### 4. Review the implementation

Open the real preview in the browser. Capture and inspect:

- desktop at 1440px wide
- mobile at 390px wide

Taking a screenshot is not review. Inspect both images for hierarchy, subject specificity, rhythm, typography, imagery, contrast, overflow, touch behavior, and fidelity to the Design Contract.

Run the fresh-context critique described in `references/visual-critique.md`. Prioritize the smallest set of changes that materially improves the result. Do not redesign a coherent page during polish.

### 5. Return the handoff

For art direction, return the complete Design Contract plus a one-sentence summary.

For critique, return:

1. verdict
2. strongest quality
3. issues ordered by visual impact
4. exact revision instructions
5. desktop and mobile acceptance checks

## Examples

### Example: consultant webinar funnel

Weak direction: "Premium dark funnel with gradients, glowing cards, and animated statistics."

Better direction: "A field-notebook editorial system built around the consultant's annotated operating framework: cropped handwritten diagrams become the signature asset, typography feels precise rather than luxurious, and verified client proof appears as full-width evidence instead of testimonial cards."

### Example: architecture studio website

Weak direction: "Minimal portfolio with a bento grid and smooth scrolling."

Better direction: "A quiet project index whose composition borrows from drawing sets: project photography carries the page, captions use drawing-number logic only where it encodes real project data, and mobile becomes a deliberate vertical exhibition rather than a collapsed desktop grid."

## Quality bar

- The direction is specific enough that swapping the brand name would break it.
- The page has one memorable signature, not a collection of effects.
- Every conversion claim is grounded in supplied evidence.
- Desktop and mobile both read as intentionally composed.
- The builder can implement without guessing at type, color, hierarchy, imagery, motion, or section rhythm.
- The final critique is based on inspected previews, not source-code imagination.
