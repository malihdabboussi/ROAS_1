# Source Code Navigation Guide

Practical entry points into a ~2.1 M-line monorepo. **Every path below was checked for existence
before it was written.** Line numbers are from the working tree at the time of this pass and will
drift; paths will not.

Terminology note: the npm scope is `@vibey/*`, the root package is `vibey-v2`, the product is
**ROAS**. Same system. See `project-mapping/01-repository-overview.md`.

## Orientation In 60 Seconds

Read these ten files in this order. Together they explain the whole system.

| #   | File                                                       | Why                                                                                                                                   |
| --- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `AGENTS.md`                                                | The operating protocol every agent and human is held to. 190 lines, and the rules are enforced by lint and hooks, not just convention |
| 2   | `pnpm-workspace.yaml` + root `package.json`                | The 20 workspaces and every script anyone actually runs (`dev:app`, `dev:back`, `dev:agentapi`, `dev:agent`, `architecture:check`)    |
| 3   | `apps/web/src/middleware.ts`                               | The gatekeeper. Nothing in the product renders until this file decides it should                                                      |
| 4   | `apps/web/src/lib/auth/access-routing.ts`                  | 110 lines of pure functions that encode the entire onboarding/access state machine                                                    |
| 5   | `apps/web/src/app/api/proxy/[...path]/route.ts`            | Every browser→backend request goes through here. Backend selection, per-user Fly machine pinning, SSE relay, header policy            |

## Conventions You Must Know

**Naming**

- npm scope `@vibey/*` (`@vibey/web`, `@vibey/api`, `@vibey/agent-api`, `@vibey/api-shared`, …); root package `vibey-v2`; product **ROAS**. The vendored gateway workspace is plain `openclaw`.
- DB tables are domain-scoped (`space_shares`, `funnel_blocks`, `agent_definitions`). **Never** a `project_` prefix. Legacy `ns_*` / `vb_*` prefixes exist in older tables.
- Don't rename files. Original names are load-bearing for the LOC allowlist and the architecture scripts.

**Frontend structure**

- `apps/web/src/features/<name>/{components,containers,hooks,services,store,types,config}` — plus `lib/`, `utils/`, `views/` where a feature needs them.
- **Features may not import other features.** Enforced by `no-restricted-imports` in `eslint.config.mjs`. Shared code goes to `@/lib/<domain>` or `@/components/<domain>`.
- **Domain barrels only.** No root mega-barrel, no reaching into another feature's private internals.
- **No direct Supabase in `apps/web`.** `no-restricted-syntax` blocks `supabase.from(...)` and names `backendGet`/`backendPost`/`backendPatch` as the replacement. Exactly four files are exempt: `middleware.ts`, `app/(auth)/callback/route.ts`, `app/api/proxy/[...path]/route.ts`, and `lib/supabase/**`.
- State is **Zustand** (25 stores) plus React Context. **No react-query, no SWR** — refetching, caching and invalidation are hand-rolled per feature.

**Backend structure**

- `apps/api/src/modules/<domain>/{controllers,services,repositories,dto}`.
- Controllers may not call `supabase.from` — `no-restricted-syntax` with a per-file allowlist.
- Auth is opt-in. Every controller needs its own `@UseGuards(AuthGuard, …)`.

**LOC gate (`eslint.config.mjs` + `scripts/arch/check-loc.mjs`)**

| Pattern                                                     | Max lines |
| ----------------------------------------------------------- | --------- |
| `**/*.controller.ts`                                        | 200       |
| `**/*.service.ts`                                           | 600       |
| `**/*.repository.ts`                                        | 400       |
| `apps/web/src/**/containers/**/*.tsx`                       | 600       |
| other `apps/web/src/features/**` and `components/**` `.tsx` | 400       |

`scripts/arch/loc-allowlist.json` grandfathers existing violations and switches `max-lines` off for
those files. `pnpm architecture:check` compares against the baseline and **currently fails on
`main`** — check whether a failure is yours before fixing it.

**Design tokens (zero exceptions)**
Every visible colour comes from a `--color-*` token via a utility class, defined with both light and
dark values. Canonical swaps: `text-white`→`text-foreground`, `text-white/60`→`text-muted-foreground`,
`bg-black`/`bg-[#hex]`→`bg-background` or `surface-card`, `border-white/10`→`border-border`,
`text-red-400`→`text-destructive`. Two legitimate exceptions, both to be marked inline: by-design
fixed surfaces (device/ad mockups simulating another product's chrome) and canvas/third-party
widgets that read token values in JS.

**Process**

- **Changelog after every change:** append to `.docs/logs/changelog$(date +%Y-%m-%d).md` with
  `## [YYYY-MM-DD HH:MM] - [TYPE]` then `What:` / `Why:` / `Impact:` / `Files:`. Never reuse
  yesterday's file. Prune logs older than 14 days.
- **Deferred work** goes in `.docs/plans/agent-follow-up-work.md`, never silently skipped.
- **Docs:** behaviour/API/schema change → `documentation/features/<feature>.md`; new shared utility →
  `documentation/utilities/<name>.md` **plus** the registry `documentation/utilities/README.md`.
- **Page `<title>` ends with `| ROAS`. All H1 headings are UPPERCASE.**
- **Never run builds automatically** — only on explicit request.
- **Never commit or push to `main`.** Branch `codex/<task>` or `claude/<task>` off fresh `main`.
- Replace, don't accumulate: when new code replaces old, delete the old in the same change.

## Where Things Are NOT

Anti-guidance. Each of these will cost you an hour if you learn it the hard way.

- **`packages/db` is not an ORM, and it is not used.** Nothing imports it, and its types were
  hand-written against the stale `supabase/schema.sql`. There is **no ORM in this repo at all** — no
  Prisma, no TypeORM. Data access is `@supabase/supabase-js` plus a raw `pg` pool where transactions
  or `LISTEN/NOTIFY` are needed.
- **There is no migration runner.** `supabase/migrations/` holds 937 `.sql` files, but nothing in the
  repo applies them, there is no `supabase/config.toml`, and `supabase start` is not wired.
  **A fresh database cannot be built from this repo.**
- **`supabase/schema.sql` is not a schema dump.** It is an early hand-written design doc covering 26
  tables. Trust the live database (via Supabase MCP) or `project-mapping/06-database-map.md`, which
  is itself derived from migrations, not from a live query.
- **`apps/openclaw` is vendored third-party code** — an in-tree copy of MIT-licensed
  `openclaw@2026.2.16`, 673 k LOC, about a third of the repo. Generally do not edit it. The ROAS
  deltas are a small set: `apps/openclaw/src/gateway-headless.ts`, `docker/openclaw.json`, and
  `docker/tools/vibey-backend/`. Any "how big is this codebase" number must subtract it.
- **`packages/api-shared/dist/` is committed to git on purpose** (`.gitignore` un-ignores it) so
  Vercel resolves prebuilt output without a package build. It **can and does desync from `src/`** —
  it is currently dirty in the working tree. Read `src/`; be suspicious of `dist/`.
- **`services/` does not mean the same thing everywhere.** In `apps/api` it's NestJS injectables. In
  `apps/web/src/features/*/services/` it's plain `fetch` wrappers around `backendGet`/`backendPost`
  — no DI, no lifecycle.
- **`apps/web/src/app/(dashboard)/` is a route group.** The parentheses are stripped from the URL, so
  there is no `/dashboard` route — even though `middleware.ts` lists `/dashboard` as protected.
  Likewise `apps/web/src/app/(auth)/config/` is a config folder, not a `/config` route.
- **`apps/api` is one Vercel serverless function**, not 336 endpoints deployed separately. A
  catch-all rewrite `/(.*)` → `/api` fronts the whole Nest app, plus four dedicated cron functions.
  One bad module takes down all 1,632 routes.
- **`apps/admin` is not the production admin surface as far as the deploy map is concerned.** It
  isn't in `CLAUDE.md`'s deploy table and was last touched 2026-07-28. It also collides with
  `apps/funnels` on port 3002, which is why root `pnpm dev` is broken — use `pnpm dev:app` etc.
- **`apps/web/src/app/(dashboard)/admin/` has one page and no index.** The real operator console is
  the separate `apps/admin` app.
- **There is no CI.** `.github/` contains only `pull_request_template.md`. No workflows, no test
  gate, no lint gate on PRs. The Husky pre-commit hook and `pnpm architecture:check` are the only
  automated gates, and the latter already fails on `main`.
- **A red test suite is not necessarily yours.** `packages/api-shared` has 2 pre-existing failures on
  clean `main`; `apps/web` lint reports pre-existing `max-lines` and `no-restricted-imports`
  violations. Baseline before you debug.
- **`*.base.ts` files numbered `-01`, `-02`, … are not a design pattern, they are LOC-gate evasion.**
  66 of them form abstract-class inheritance chains (`SpaceAutomationService` spans 19 files,
  ~10.5 k LOC). The gate only inspects `*.service.ts`, so the chain is invisible to it. Don't imitate
  it; don't assume the "service" you found is the whole service.
- **HTTP status codes lie on the chat path.** The proxy returns 200 with an SSE body even when the
  request failed; errors arrive as in-band `{type:'error'}` events.
- **`scripts/roas/deploy-railway-workers.sh` does not deploy.** It prints secret `KEY=value` pairs to
  stdout. Never run it, never capture its output. For Fly, only
  `bash scripts/roas/deploy-fly-runtimes.sh` — never raw `flyctl deploy`.
- **`.vercel-env` contains the single word `staging` and its purpose is unknown.** `deno.lock`,
  `embed-form-test.html` and `skills-lock.json` at the root are leftovers or narrow tooling, not part
  of the pnpm build.
